# ADR-001: Use Django Admin for Managing Services and Incidents

## Status

Accepted

## Context

Our team originally had three members, but one team member dropped the project. We now have two team members working on the project.

Because we have a smaller team, we want to avoid spending extra time building features that Django already provides.

Our project needs a way for team members to manage services and incidents. We needed to decide whether to build our own management interface or use Django's built-in Admin feature.

## Decision

We decided to use **Django Admin** to manage services and incidents.

Using Django Admin allows our two-person team to manage project data without having to build a separate management dashboard from scratch.

This lets us spend more time working on the main service monitoring and incident features.

## Alternatives Considered

### Alternative 1: Build a Custom Dashboard

We considered building our own dashboard for managing services and incidents.

A custom dashboard would give us more control over the design and user experience. However, it would require more development and testing.

With only two team members, we decided that the extra development time was not necessary for the current project.

### Alternative 2: Build a Separate Frontend

We also considered creating a separate frontend using a JavaScript framework such as React.

This could provide more flexibility for the interface, but it would add another technology and require more code to maintain.

We decided to keep the project simpler by using Django Admin.

## Consequences

### Benefits

* Less code needs to be developed.
* The team does not have to build a management dashboard from scratch.
* Services and incidents can be managed through Django Admin.
* The two-person team can focus on the main project features.
* The project has fewer moving parts to maintain.

### Trade-offs

* Django Admin has less design flexibility than a custom dashboard.
* The interface may not be as user-friendly for regular service users.
* More customized workflows may require additional development later.
* The team will be working within the structure provided by Django Admin.

The team accepted these trade-offs because using Django Admin reduces development work and allows the two-person team to focus on the main goals of the project.
