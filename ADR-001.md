# ADR-001: Use Django Admin for Managing Services and Incidents

## Status

Accepted

## Context

Our team originally had three members, but one team member dropped the project. We now have two team members working on the project.

Our project needs a way to manage services and incidents. We needed to decide if we should build our own management page or use a feature that Django already provides.

Since we now have a smaller team, we want to avoid spending too much time building features that are not the main focus of our project. We also want to keep the project simple and easier to maintain.

## Decision

We decided to use **Django Admin** to manage services and incidents.

The team agreed that Django Admin gives us the basic tools we need without having to build a separate management dashboard. This allows us to spend more time working on the main service monitoring and incident features.

## Alternatives Considered

### Alternative 1: Build a Custom Dashboard

We considered building our own dashboard for managing services and incidents. This would give us more control over how the dashboard looks and works.

However, building a custom dashboard would require more development and testing. With only two team members, we decided that the extra work was not necessary for the current project.

### Alternative 2: Build a Separate Frontend

We also considered creating a separate frontend using a JavaScript framework such as React. This could provide more flexibility for the interface.

However, this would add another technology to the project and require more code for us to develop and maintain. We decided to keep the project simpler by using Django Admin instead.

## Consequences

### Benefits

* Less code needs to be developed.
* The team does not have to build a management dashboard from scratch.
* Services and incidents can be managed through Django Admin.
* The two-person team can focus on the main project features.
* The project has fewer moving parts to maintain.

### Trade-offs

* Django Admin has less design flexibility than a custom dashboard.
* The interface may not be as user-friendly for regular service users.
* More customized workflows may require additional development later.
* The team will be working within the structure provided by Django Admin.

The team accepted these trade-offs because using Django Admin reduces development work and allows the two-person team to focus on the main goals of the project.
